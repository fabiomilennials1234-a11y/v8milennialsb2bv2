# 2026-04-16

## Busca digitavel de produto + quantidade por item de proposta

**Task**: Melhorar UX de selecao de produto (busca digitavel) e suportar quantidade/unidades por item na proposta.

**Diagnostico**: Selecao de produto usava Select simples sem busca — ruim para catalogos maiores. `pipe_proposta_items` armazenava apenas `product_id` e `sale_value`, sem `quantity` nem `unit_price`. TinyERP assumia `quantidade: 1` hardcoded.

## Mudancas aplicadas (branch `develop`)

### DBA — Migration
- [20260912000000_add_quantity_unit_price_to_proposta_items.sql](../../../../supabase/migrations/20260912000000_add_quantity_unit_price_to_proposta_items.sql)
  - `quantity INT NOT NULL DEFAULT 1` com CHECK > 0
  - `unit_price NUMERIC` com CHECK >= 0
  - CHECK `sale_value >= 0`
  - Backfill: `unit_price = COALESCE(sale_value, 0)` para items existentes
  - `sale_value` mantido como total da linha para backward compatibility com 6+ RPCs de dashboard

### Frontend — ProductCombobox + Quantidade
- [ProductCombobox.tsx](../../../../src/components/proposals/ProductCombobox.tsx) — novo componente Popover + Command (cmdk) com busca por nome e SKU
- [CreateProposalModal.tsx](../../../../src/components/proposals/CreateProposalModal.tsx) — combobox + campos Qtd / Preco Unit / Total por linha
- [ProposalDetailModal.tsx](../../../../src/components/proposals/ProposalDetailModal.tsx) — mesma mudanca (deprecated mas ainda em uso)
- [PropostasContext.tsx](../../../../src/components/leads/funnel-contexts/PropostasContext.tsx) — mesma mudanca no drawer de lead
- [usePipePropostaItems.ts](../../../../src/hooks/usePipePropostaItems.ts) — interface atualizada com quantity, unit_price, sku no join
- [types.ts](../../../../src/integrations/supabase/types.ts) — `pipe_proposta_items` com campos novos (workaround manual ate regenerar)

### Backend — TinyERP
- [tinyerp-push-order/index.ts](../../../../supabase/functions/tinyerp-push-order/index.ts) — usa `quantity` e `unit_price` reais; fallback para `sale_value` em items legados
- [TinyErpConfirmOrderDialog.tsx](../../../../src/components/proposals/TinyErpConfirmOrderDialog.tsx) — exibe quantidade no resumo quando > 1

## Decisao de modelagem

`sale_value` permanece como campo computado (`quantity * unit_price`) e fonte de verdade para:
- `get_dashboard_metrics_v8` e variantes
- `get_product_ranking`
- `get_ranking_data`
- Upsell module RPCs
- Ghost master view

Isso garante zero breaking change em analytics existentes.
