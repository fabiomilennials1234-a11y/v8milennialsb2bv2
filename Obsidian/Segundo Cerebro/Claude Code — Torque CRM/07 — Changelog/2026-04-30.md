# 2026-04-30

## Fix sync meeting_date ⇄ compromisso_date + move_pipe_record fail-closed

**Tipo:** fix
**Branch sugerida:** `fix/meeting-date-sync`
**Agentes:** Architect, Backend, Frontend, Security, QA, Documenter
**Escopo:** medium

### Problema
Alteração de data/hora de reunião não persistia consistentemente entre `pipe_confirmacao.meeting_date` e `leads.compromisso_date`. 4 causa-raízes:
- CR-1: `useUpdatePipeConfirmacao` checava `move_pipe_record` sempre que `updates.status` aparecia no payload, mesmo sem mudança efetiva.
- CR-2: Sem sync entre as duas tabelas.
- CR-3: `selectedItem` em `PipeConfirmacao.tsx` ficava stale após refetch.
- CR-4: Form de Leads salvava `compromisso_date` sem propagar para o pipe.

### Solução
- `pipe_confirmacao.meeting_date` é fonte operacional; `leads.compromisso_date` é espelho.
- Sync client-side em hooks centrais (`useUpdatePipeConfirmacao` + `useUpdateLead`). Sem migration, sem RPC nova.
- `useUpdatePipeConfirmacao` agora faz SELECT-then-compare antes de checar `move_pipe_record` (fail-closed em loading).
- `selectedItem: any` → `selectedItemId: string | null` com lookup derivado.
- Microcopy de erro custom no `ConfirmacaoContext`.

### Arquivos
- `src/hooks/usePipeConfirmacao.ts` — SELECT-then-compare, fail-closed, sync `meeting_date → compromisso_date`, filtros `.eq("organization_id")`, invalidate `["leads"]`.
- `src/hooks/useLeads.ts` — sync inverso `compromisso_date → meeting_date` (UPDATE puro, best-effort).
- `src/pages/PipeConfirmacao.tsx` — `selectedItemId` + lookup derivado.
- `src/components/leads/funnel-contexts/ConfirmacaoContext.tsx` — microcopy custom para erro de permissão.

### Notas
- Verificação Security S6: nenhum trigger DB recalcula `pipe_confirmacao.status` a partir de `meeting_date`. Triggers existentes (`update_updated_at`, `enqueue_webhooks`, `dispatch_rules`, `sync_from_lead`, `sync_owners_to_lead`, `stage_change` log, `validate_status`, `workflow_meeting_confirmed`) não causam escalada implícita de stage server-side.
- Decisão D3: Architect propôs opção (c) "caller omite", Security vetou por bypass trivial. Decisão final: opção (b) — SELECT-then-compare dentro do hook.
- Race window sub-segundo entre UPDATE no pipe e UPDATE no lead — last-write-wins.
