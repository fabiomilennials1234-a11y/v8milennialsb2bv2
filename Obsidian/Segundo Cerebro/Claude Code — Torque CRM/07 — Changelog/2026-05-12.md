# 2026-05-12 — RPC Consolidation + Cron Health Check

## Contexto

Automações (workflows, pipe rules, campaign dispatch, cron jobs) param de funcionar intermitentemente em prod. Investigação sistemática revelou **5 root causes simultâneas**, todas decorrentes de migration churn dos últimos 7 meses.

## Root causes confirmadas

1. **Overload duplicada `claim_workflow_executions`**: 1-arg regredida vs 2-arg hardenizada coexistindo. PostgREST escolhia a 1-arg (sem per_org_cap, sem race-fix predicate replication).
2. **Overload duplicada `fire_workflow_trigger`**: 4-arg sem chain_depth vs 5-arg com guard. PG triggers chamam 4-arg → loop guard bypassed.
3. **CRON_SECRET drift sem alerta**: `cron_config.cron_secret` (tabela) vs `CRON_SECRET` env desacoplados; rotação de um sem o outro = parada silenciosa.
4. **`net._http_response` queue growth**: sem cleanup, pg_net trava silenciosamente.
5. **wait_response sem callers**: RPC existia desde 20260901 mas zero edge functions chamavam → workflows stuck até timeout.

## Mudanças

### Migrations criadas

- `20261001000000_consolidate_workflow_rpcs.sql` — DROP+CREATE única overload por RPC, com `DO $verify$` anti-regressão
- `20261001000001_pgnet_cleanup_cron.sql` — cron daily 03:00 UTC para `DELETE FROM net._http_response WHERE created < NOW() - INTERVAL '7 days'`
- `20261001000002_resolve_wait_response_by_phone.sql` — RPC phone-keyed que normaliza + delega ao `resolve_wait_response`
- `20261001000003_schedule_cron_health_check.sql` — cron a cada 5min via `invoke_cron_health_check()`

### Edge function criada

- `supabase/functions/cron-health-check/` — detecta CRON_SECRET drift via probe HTTP, loga em `runtime_logs` + Sentry quando unhealthy
- Lógica pura extraída em `health-check.ts` (testável em vitest)

### Edge functions editadas

- `whatsapp-webhook/index.ts` — fire-and-forget `resolve_wait_response_by_phone` em inbound
- `sz-chat-webhook/index.ts` — idem (paridade)

### Config

- `supabase/config.toml` — registra `[functions.cron-health-check] verify_jwt = false`

### Tests

- `tests/integration/claim-workflow-executions.test.ts` — single overload, per_org_cap, waiting_response reclaim, race safety
- `tests/integration/fire-workflow-trigger-chain-depth.test.ts` — chain depth guard com/sem parent, block em max
- `tests/integration/resolve-wait-response-by-phone.test.ts` — normalização phone, idempotência, isolamento de org
- `tests/unit/cron-health-check.test.ts` — 8 testes da lógica pura (healthy/unhealthy/drift/null probe)

- Migração pg_cron → push-based scheduler (Inngest/Trigger.dev)

# 2026-05-12 — Chat Bubble: filtro de instância

## Mudanças

- **Chat Bubble**: adicionado switcher de instância no header da lista para usuários com ≥2 instâncias permitidas (filtro visual client-side, persistido por user no localStorage).

## Arquivos tocados

- `src/components/chat/bubble/ChatBubbleInstanceSwitcher.tsx` — novo, Popover Radix 260px com "Todas as conversas" + lista alfabética + status muted + Check no selecionado
- `src/contexts/ChatBubbleContext.tsx` — novo state `listInstanceFilter`, persiste em `chat-bubble:list-filter:${userId}`, auto-reset quando instância filtrada some, auto-sync no `open({instanceId})`
- `src/components/chat/bubble/ChatBubblePanel.tsx` — passa `titleSlot` (switcher) ou `singleInstanceName` (1 instância) pro header; passa `filterInstanceId` + `onResetFilter` pra lista
- `src/components/chat/bubble/ChatBubbleHeader.tsx` — modo `list` aceita `titleSlot` (substitui "Conversas") e `singleInstanceName` (subtítulo 10px)
- `src/components/chat/bubble/ChatBubbleConversationList.tsx` — nova prop `filterInstanceId`, filtro client-side pós-`useQueries` (cache compartilhado intacto), variant `filtered-empty` no empty state
- `src/components/chat/bubble/ChatBubbleEmptyState.tsx` — discriminated union, variant `filtered-empty` com `instanceName` + `onReset`
- `tests/unit/chat-bubble-instance-filter.test.tsx` — novo, 9 testes (persist, auto-reset, switcher UI, empty filtered)
- `tests/unit/chat-bubble-context.test.tsx` — estendido com 7 testes do filter

- `Obsidian/.../06 — Features/Chat/chat-bubble-instance-filter.md` — feature note
- `Obsidian/.../00 — INDEX.md` — link adicionado

## Decisões

- Filtro client-side (cache `useQueries` reusado com `/chat` continua compartilhado).
- Badge FAB nunca filtra (atalho de "tem coisa pra olhar").
- `useQueries` itera sobre `instances` completo — filtrar antes mudaria hook count entre renders.
- Auto-sync no `open({instanceId})`: deep-link de uma conversa implica intent de focar nessa instância.

- Nenhum. Feature frontend-only, sem schema/edge function.
