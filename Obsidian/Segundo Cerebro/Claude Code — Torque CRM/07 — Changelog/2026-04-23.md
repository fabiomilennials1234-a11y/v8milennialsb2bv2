# 2026-04-23 — fix(copilot): eliminar fallback silencioso + bridge Uazapi→agent + tenant isolation

## Incidente

Usuário perguntou "a granel quais sabores tem?" no WhatsApp e recebeu **"Desculpe, houve um problema ao processar sua mensagem."** (54 chars). Logs de prod (72h): dezenas de `messageLength: 54` com `action: SEND_DOCUMENT`. Nenhum log `LLM call #3`, descartando exhaustão do MAX_TOOL_TURNS.

## Diagnóstico (7 causas raízes confirmadas)

| ID | Causa |
|---|---|
| CR-1 | `agent-engine.ts:222` — LLM retorna `content:null + tool_call non-inline` → `assistantMessage=''` → fallback silencioso. |
| CR-2 | Histórico persiste assistant+tool_calls com `content:''` — viola contrato OpenAI (deve ser `null`). |
| CR-3 | `tool_calls[0]` — descarte silencioso dos demais tool_calls. |
| CR-4 | `finish_reason` nunca consultado. Truncamento passa como sucesso. |
| CR-5 | `loadConversation` ignora `agent_id` e `organization_id` — tenant bleeding / maybeSingle() pode quebrar. |
| CR-6 | `whatsapp-webhook` (Uazapi) nunca invoca `agent-message`. Orgs em Uazapi = Copilot inoperante. |
| CR-7 | `identifyTenant` sem org_id busca cross-tenant → security boundary fraca. |

## Implementação

**Agent-engine** ([supabase/functions/agent-message/agent-engine.ts](../../../../supabase/functions/agent-message/agent-engine.ts)):
- Forced-text turn: após loop multi-turn, se `finalAssistantMessage` vazio, chama LLM de novo com `tool_choice:'none'` forçando texto.
- Telemetria por invocação: `turns_used`, `tools_called`, `finish_reasons`, `content_null_turns`, `forced_text_turn_used`, `forced_text_succeeded`, `fallback_used`, `truncated`.
- `loadConversation` agora filtra `lead_id + agent_id + organization_id` com `.order().limit(1)`.
- `processLLMResponse` retorna `extraToolCalls` + `finishReason`; skip silencioso de tool_calls com JSON corrompido.

**OpenRouter client** ([openrouter-client.ts](../../../../supabase/functions/agent-message/openrouter-client.ts)):
- `convertMessages` respeita contrato OpenAI: `content:null` em assistant+tool_calls; coage null→"" em assistant sem tool_calls.

**Agent-message entry** ([agent-message/index.ts](../../../../supabase/functions/agent-message/index.ts)):
- `organization_id` agora obrigatório no body. Retorna 400 se faltante.
- Removido fluxo legado de lookup cross-tenant por telefone.

**Whatsapp-webhook (Uazapi)** ([whatsapp-webhook/index.ts](../../../../supabase/functions/whatsapp-webhook/index.ts)):
- Após `upsert` em `whatsapp_messages`, mensagens `direction:'incoming'` com texto disparam fetch fire-and-forget para `agent-message` com payload unificado. Log em `runtime_logs.uazapi_agent_message_dispatched`.

## Validação

- `tests/unit/agent-engine-openrouter-client.test.ts` — **6 testes** cobrindo contrato content/tool_calls.
- `tests/unit/agent-engine-fallback.test.ts` — **7 testes** cobrindo processLLMResponse (content:null, multi-tool, finish_reason, invalid JSON, no choices) + loadConversation tenant isolation.
- `npx tsc --noEmit`: 0 erros (ignora erros pré-existentes de URL imports Deno).
- Full suite: 2470+ tests passando. 2 falhas pré-existentes ao merge de develop (evolution-api.test imports drift + dompurify missing na build — não relacionadas).
- Security gate aprovado.

## Impacto

1. Pergunta "a granel quais sabores tem?" → LLM chama `search_knowledge` inline (loop atual) OU, no pior caso de retorno vazio, o forced-text turn fornece a resposta. **Fallback silencioso eliminado estruturalmente.**
2. Orgs em Uazapi recuperam Copilot funcional.
3. Tenant isolation fortalecida.
4. Observabilidade por invocação permite diagnóstico sem depender de print de cliente.

## Pendente

- Deploy em prod (edge functions: agent-message, whatsapp-webhook) após merge.
- Enfileirar `extraToolCalls` em paralelo (follow-up — hoje WARN log).
