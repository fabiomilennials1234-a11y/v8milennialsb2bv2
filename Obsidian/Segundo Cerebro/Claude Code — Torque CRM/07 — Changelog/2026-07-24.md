## Decisões
- **Feed vive no gate, não no `UazapiClient`.** O threading de `instanceId` no client (`feedReputationBestEffort`) segue dormante por design — feed exclusivo do choke evita double-count. Nenhum fix de propagação foi necessário: `UazapiError { status:463 }` chega ao gate intacto (`UazapiProvider.sendText/Media` não captura; `request()` monta o status no ramo 4xx).
- **Best-effort/fail-soft awaited** no ramo de erro (consistente com a telemetria pós-envio): completa antes do isolate suspender, mas nunca altera o desfecho — erro original re-lançado sem tocar.
