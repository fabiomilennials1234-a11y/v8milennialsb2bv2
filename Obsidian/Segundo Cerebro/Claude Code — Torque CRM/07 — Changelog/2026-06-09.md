# 2026-06-09

## Mudanças
- **billing/identity**: fix do guard de subscription — erro de transporte (timeout de RPC) NÃO bloqueia mais o usuário como "Assinatura Expirada". Política fail-open: novo `status:'unknown'`, retry curto na RPC, bloqueio só em status terminal afirmado pelo DB.
- **copilot**: `useCopilotSubscription` não nega gestão por erro transitório (`'unknown'` trata como acesso).

## Contexto do incidente
- Org **Grafica Cauta** (`589f6a52-…`) aparecia "Assinatura Expirada" para a usuária `comercial3@graficacauta.com.br` (membro **ativo**, logou 06-09). Org 100% sã em prod: `subscription_status=active`, `billing_override=true` ("Vendido", desde 05-26), `expires_at=2126`.
- Causa raiz: `checkSubscription` (`src/modules/billing/lib/subscription.ts`) tratava QUALQUER erro de RPC (`error || !data`) como `{status:'expired', isBlocked:true}`. Prod soltando `HTTP 544 connection timeout` intermitente → fallback hardcoda expired → `SubscriptionProtectedRoute` renderiza `SubscriptionBlockedPage`. Atingia qualquer org sob carga.
- Bônus: `Navigate("/subscription-required")` no guard apontava para rota inexistente (beco sem saída) — também corrigido para fail-open.

## Arquivos tocados
- `src/modules/billing/lib/subscription.ts` — `SubscriptionStatus.status` ganha `'unknown'`; `checkSubscription` com retry (`RPC_RETRY_DELAYS_MS = [150,400]`) + fail-open via `unknownSubscription()`.
- `src/modules/identity/components/SubscriptionProtectedRoute.tsx` — `!subscription || status==='unknown'` → render children (antes redirecionava pra rota morta).
- `src/modules/copilot/hooks/useCopilotSubscription.ts` — `'unknown'` conta como acesso.
- `tests/unit/subscription.test.ts` — testes obsoletos (que afirmavam o bug) reescritos; +regressões (retry, recovery, terminal block, override soberano).
- `src/modules/billing/CLAUDE.md` — área frágil documentada.

## Decisões
- Guard de subscription é **DISPLAY/UX**, não fronteira de segurança (enforcement real = RLS + RPCs server-side). Logo fail-open em erro de transporte é a escolha correta — bloquear pagante por timeout é pior.
