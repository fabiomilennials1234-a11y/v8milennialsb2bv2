# Changelog — 2026-04-27

## Workflow Time-Aware Window (Onda 5)

Extensão do node `wait_business_window` no workflow visual: agora suporta múltiplas janelas customizáveis (até 6) com 3 ações distintas — `pass`, `hold_until:X`, `route:X`. Reusa resolver `time-context.ts` deployado ontem (Copilot Time-Aware Behavior).

### Motivação
Node legacy só sabia 1 coisa: pausar execução fora do horário comercial até janela abrir. Sem branching, sem múltiplas janelas, sem comportamento diferente por horário. Cliente queria controle equivalente ao do Copilot — "domingo vai pra outro caminho", "madrugada segura até manhã", "fds manda só msg curta".

### Schema (migration 20260921000000_workflow_wait_business_window_v2)

Schema do node estendido em `src/types/workflow.ts`:
```ts
WaitBusinessWindowNodeData = {
  // Legacy preservado (retrocompat fallback)
  days?, startTime?, endTime?, timezone?
  // Novo (opt-in)
  windows?: Array<{
    id, name, days, start, end,
    action: "pass" | `hold_until:${name}` | `route:${branchKey}`
  }>;
  mode?: "hold" | "route" | "hybrid";
}
```

### Resolver shared
`computeNextWindowStart(windows, name, tz, from)` adicionado em `time-context.ts`. Calcula próximo timestamp em que janela com nome X abre. Worst-case 14×24×60 iterações (sub-ms V8). Usado pelo executor pra setar `next_run_at` no `hold_until:X`.

`windowMatches` exportado (era interno) pra ser reusado.

### Workflow-executor refactor (workflow-executor.ts:536)
3 ações suportadas:
- **pass**: continua pela edge default
- **hold_until:X**: pausa, `next_run_at = computeNextWindowStart(X)`, re-evaluação no próximo cron
- **route:X**: sai pelas edges com `sourceHandle === X` (saída múltipla nomeada)

Fallback se nenhuma janela ativa: hold até primeira janela com `action=pass` abrir. Legacy single-window mantido se `windows[]` vazio.

### Frontend
- `WaitBusinessWindowNode.tsx` — handles dinâmicos: 1 por janela com action route (cor amber) + 1 default (cor emerald) na parte inferior
- `WaitBusinessWindowPanel.tsx` (sidebar config) — refator pesado: nome+timezone+modo global, lista até 6 janelas (chips dias + horários + dropdown action). Action dropdown abre input adicional pra hold_until (select de janelas) ou route (input chave string)

### Backfill
2 workflows Milennials migrados automaticamente pela migration:
- `ab7a35b8-23ac-4221-a86a-55d97c8fc8f6`
- `2e8de418-11b9-4b01-ad82-988debb909c3`

Comportamento idêntico ao anterior preservado: 1 janela "Comercial" derivada de days/startTime/endTime + action=pass + mode=hold.

### Mapeamento dias legacy → EN
`__map_legacy_days(jsonb)` — função SQL temporária convertendo seg/ter/qua/qui/sex/sab/dom (PT) pra mon/tue/wed/thu/fri/sat/sun (EN). Dropada após backfill.
