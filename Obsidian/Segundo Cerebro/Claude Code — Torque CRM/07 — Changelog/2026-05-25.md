## 2026-05-25 — Fix permissões consolidação (PRD #408) órfão

### Mudanças
- **DB**: nova migration `20261103000000_drop_legacy_org_role_permissions_seed_trigger.sql` derruba o trigger `tg_seed_org_role_permissions` em `organizations` e a função `seed_member_org_role_permissions()`. Eram órfãos deixados pela `20261032000002` (CASCADE drop de tabela não derruba funções PL/pgSQL que a referenciam no corpo). Trigger estava bloqueando criação de nova org com erro `relation "public.organization_role_permissions" does not exist`.
- **Edge fn**: `_shared/permission_engine.ts` — reescrita de `checkOrgPermission()`. Agora mapeia legacy permission_key → feature_key via `LEGACY_ORG_KEY_TO_FEATURE_KEY` (mesmas 5 keys de `user_has_org_permission`), consulta `member_feature_permissions` + `feature_permissions.default_value`, fail-closed para keys não mapeadas. Removidas todas as queries em `team_member_org_permissions` e `organization_role_permissions` (tabelas dropadas).
- **Tests**: `tests/unit/shared-permission-engine.test.ts` atualizado — delete_lead agora cobre member_feature_permissions + feature default; bloco `organization_role_permissions cascade` reescrito para refletir mapping/fail-closed; move_pipe_record agora valida fail-closed para non-admin.

### Arquivos tocados
- `supabase/migrations/20261103000000_drop_legacy_org_role_permissions_seed_trigger.sql` — drop trigger + função órfãos
- `supabase/functions/_shared/permission_engine.ts` — checkOrgPermission via feature_permissions
- `tests/unit/shared-permission-engine.test.ts` — atualizados 9 testes

### Impacto comportamental (importante)
- Legacy keys mapeadas → feature_key (5 keys mantêm comportamento equivalente):
  - `see_unassigned_cards` → `leads.view_unassigned`
  - `see_subordinates_cards` → `leads.view_subordinates`
  - `see_general_info` → `leads.view_general_info`
  - `see_all_leads` → `leads.view_all`
  - `can_delete_leads` → `leads.delete`
- Legacy keys NÃO mapeadas (fail-closed para non-admin) — **mudança de comportamento**:
  - `can_create_leads` (action `create_lead`)
  - `can_export_leads` (action `export_leads`)
  - `can_move_pipe_records` (action `move_pipe_record`)
  - `can_manage_campaigns` (action `trigger_campaign`)
- Admins seguem allowed para tudo (branch antes de chegar em checkOrgPermission).

### Decisões
- Não reseedar `organization_role_permissions` (tabela dropada). Defaults vêm de `feature_permissions.default_value` (seedados em `20261032000000`).
- Não criar mapeamento extra para os 4 legacy keys não-mapeados — alinha com `user_has_org_permission()` (PRD #408) e brief explícito. Tratamento equivalente exigirá criar feature_keys novos (`leads.create`, `leads.export`, `pipeline.move_cards`, `campaigns.edit`) e reescrever `ACTION_TO_FEATURE` em vez de `ACTION_TO_ORG_PERMISSION` — follow-up.
