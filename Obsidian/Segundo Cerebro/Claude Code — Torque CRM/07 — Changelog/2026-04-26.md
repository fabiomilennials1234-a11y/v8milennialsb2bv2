# 2026-04-26 — Fix createInstance no whatsapp-api-proxy (Evolution)

## Bug

Frontend ao criar instância WhatsApp recebia:

```
whatsapp-api-proxy: Edge Function returned a non-2xx status code
```

Causa raiz: branch `createInstance` inseria `provider: "uazapi"` e chamava `getWhatsAppProvider(newRow)` logo após o INSERT. Factory para Uazapi faz RPC `get_uazapi_credentials` para montar `UazapiProvider` com token por-instância. Token só é gravado pelo próprio `provider.createInstance()` (via `set_uazapi_credentials`) → RPC vazia → throw `"No uazapi credentials found for instance <id>"` → 500.

Bug duplo:
1. Provider errado: sistema opera com **Evolution**, não Uazapi (Uazapi é roadmap futuro/migração).
2. Bootstrap: factory Uazapi exigia credencial que só existe após o passo que ela deveria habilitar.

## Fix

Arquivo: `supabase/functions/whatsapp-api-proxy/index.ts`

1. Insert agora usa `provider: "evolution"` (era `"uazapi"`).
2. `EvolutionProvider` instanciado direto na branch `createInstance` — Evolution usa `EVOLUTION_API_KEY` global, sem credencial por-instância.
3. Cleanup do row órfão se `provider.createInstance()` falhar — evita que a constraint `UNIQUE(organization_id, instance_name)` bloqueie retries com mesmo nome.

Demais branches (getStatus, connectQR, deleteInstance, sendText, etc.) continuam usando a factory `getWhatsAppProvider` — para Evolution ela só lê `instance.instance_name` do row, sem RPC.

## Round 2 — Healthcheck Evolution + status enum

**Sintoma 2**: healthcheck mostrava "Evolution conectada" mas botão "Testar conexão" no `WhatsAppSettings` retornava "Serviço indisponível".

Causas:
1. `check-api-health` edge function não probava Evolution — só Uazapi. Master dashboard `ApiStatusTab` tinha metadata p/ "Evolution API" mas backend nunca retornava esse `service`.
2. `WhatsAppSettings.handleTestConnection` filtrava `r.service === "Uazapi"` (literal). Resultado vazio → `uazapi?.error || uazapi?.status || "Serviço indisponível"` → toast "Falha Uazapi: Serviço indisponível".

Fixes:
- `supabase/functions/check-api-health/index.ts`: nova função `checkEvolution()` (GET na raiz da `EVOLUTION_API_URL` com header `apikey`).
- `src/components/settings/WhatsAppSettings.tsx`: filtro alterado p/ `r.service === "Evolution API"`, toast e label corrigidos.

**Sintoma 3**: writes inválidos para `whatsapp_instances.status` (legado Uazapi).
- Status `"open"` e `"close"` não estão no `CHECK (status IN ('disconnected','connecting','connected','error'))`.
- Trocados por `"connected"` e `"disconnected"` no `whatsapp-api-proxy`.

Deployed: `whatsapp-api-proxy` + `check-api-health` (`jsjsmuncfkbsbzqzqhfq`).
