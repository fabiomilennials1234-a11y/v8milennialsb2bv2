# 2026-04-24 — Fix import leads em Custom Pipelines

## Bug reportado

Usuários clicavam em "Importar" dentro de funis customizados, UI mostrava sucesso, mas a lista não entrava no funil. Funis padrões (`pipe_whatsapp`, `pipe_confirmacao`, `pipe_propostas`) funcionavam normal.

## Root cause

`custom_pipe_entries.assigned_to` referenciava `profiles(id)` — **única tabela de pipeline no sistema assim**. Todas outras (`pipe_whatsapp`, `pipe_confirmacao`, `pipe_propostas`, `pipe_distribution`, `campanhas`, `upsell`) referenciam `team_members(id)`.

Cadeia da falha:
1. Frontend enviava `team_members.id` via `useTeamMembers()` → `memberOptions`
2. Edge function `importToCustomPipeline` repassava direto pra `assigned_to`
3. Postgres rejeitava com FK violation (team_members.id ≠ profiles.id)
4. INSERT/UPDATE em `custom_pipe_entries` não capturava `error` nem usava `.select().single()` — falha silenciosa
5. `report.created++` já tinha rodado na linha 997 (insert em `leads` funcionou), UI reportava sucesso
6. Funil vazio

Bug era intermitente: se usuário escolhesse "Sem atribuição" e CSV não tivesse coluna `seller_name`, `assigned_to = null` → FK aceitava null → lead entrava. Qualquer atribuição quebrava.

Master virtual (`master-virtual-<uuid>`) também quebrava (UUID inválido).

## Fix aplicado (3 camadas)

### 1. Migration (`supabase/migrations/20260918000000_fix_custom_pipe_entries_assigned_to_fk.sql`)

- Converte rows existentes: `profiles.id → team_members.id` via match por `user_id` + `organization_id` (preserva multi-tenancy)
- Usa `DISTINCT ON (cpe.id) ORDER BY is_active DESC, updated_at DESC` quando múltiplos team_members ativos por profile/org
- Nullifica órfãos sem match
- DROP FK antiga (`profiles`) + ADD nova (`team_members` ON DELETE SET NULL)
- Idempotente via DO blocks
- `RAISE NOTICE` com count de rows convertidas/nullificadas (audit)

### 2. Edge function (`supabase/functions/import-leads/index.ts`)

- Captura `error` no INSERT/UPDATE de `custom_pipe_entries` + `.select().single()`
- Se falha e lead era novo: decrementa `report.created`, incrementa `report.rejected`, push em `report.errors`
- `console.error` com context (leadId, orgId, pipelineId, stageId, assignedTo) — sem PII
- `truncateErr(msg, 200)` evita vazar mensagens longas do Postgres

### 3. Frontend (`src/components/custom-pipelines/ImportCustomPipelineContent.tsx`)

- `memberOptions` filtra `isVirtualTeamMember(m.id)` + `m.is_active !== false`
- Mensagem pós-import condicional: se `lastReport.errors.length > 0`, exibe quantos entraram + aponta pros erros

### 4. Testes (`tests/integration/lead-import.test.ts`)

Regression suite cobrindo:
- INSERT em `custom_pipe_entries` com `team_members.id` deve funcionar pós-migration
- UUID inválido deve retornar FK violation observável (não silenciosa)
- `assigned_to = null` deve funcionar (responsável opcional)

## Security gate

Security aprovou com condições (todas aplicadas):
- Migration: `RAISE NOTICE` com count + uso de `DISTINCT ON` pra multi-match determinístico
- Edge function: `truncateErr` limita vazamento de error.message
- Deploy order: **migration antes da edge function**, staging antes de prod

## Deploy plan
