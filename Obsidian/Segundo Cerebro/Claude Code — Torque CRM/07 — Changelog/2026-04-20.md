# 2026-04-20

## Fix layout do Chat WhatsApp — corte vertical e horizontal

**Task**: Chat cortando na UI (composer sumindo abaixo da dobra; conteudo clipado na direita). Tratado como bug de producao com systematic-debugging: nenhum fix antes de confirmar causa raiz via evidencia no codigo.

### Causa raiz (3 defeitos simultaneos)

1. **Vertical (primario)** — [WhatsAppChat.tsx:2327](../../../../src/components/chat/WhatsAppChat.tsx) usava `h-[calc(100vh-4rem)] max-h-[calc(100vh-4rem)]`. Erros:
   - TopNav real e `h-14` (3.5rem = 56px) conforme [index.css:256](../../../../src/index.css), nao 4rem → 8px a mais.
   - Ignorava `py-6 lg:py-8` do [MainLayout.tsx:13](../../../../src/components/layout/MainLayout.tsx) → +48-64px.
   - Total: chat 56-72px mais alto que o container. `<main>` tinha `overflow-auto`, gerava scroll externo e empurrava o composer pra fora da dobra.

2. **Horizontal (secundario)** — [WhatsAppChat.tsx:2367](../../../../src/components/chat/WhatsAppChat.tsx) (Chat Window flex child) sem `min-w-0`. Em flex, `min-width: auto` default deixa filhos com `min-w-[200px]` (composer) ou texto longo forcarem largura maior que a fatia. O `overflow-hidden` do pai (2327) clippava na direita.

3. **Causa habilitadora** — MainLayout nao propagava altura via flex chain. Wrapper interno era bloco com padding, sem flex/min-h-0. Por isso o chat recorreu a math de viewport hardcoded — sintoma, nao solucao.

### Evidencia comparada no codebase

- [ApiDocs.tsx:85](../../../../src/pages/ApiDocs.tsx) usa `h-[calc(100vh-3.5rem)]` — valor CORRETO. Confirma que 4rem era chute.
- [AutomacoesEditor.tsx:299](../../../../src/pages/AutomacoesEditor.tsx) usa `-m-6` pra neutralizar o padding do MainLayout — prova que o problema e conhecido e recorrente.

### Correcao (3 arquivos, 6 linhas)

**[MainLayout.tsx](../../../../src/components/layout/MainLayout.tsx)** — propaga altura pela cadeia flex:
```diff
- <div className="flex flex-col min-h-screen bg-background" data-layout="main">
+ <div className="flex flex-col h-screen bg-background" data-layout="main">
    <TopNavigation />
-   <main className="flex-1 overflow-auto">
-     <div className="px-6 lg:px-10 xl:px-12 py-6 lg:py-8 max-w-[1600px] mx-auto w-full">
+   <main className="flex-1 min-h-0 overflow-auto">
+     <div className="px-6 lg:px-10 xl:px-12 py-6 lg:py-8 max-w-[1600px] mx-auto w-full min-h-full flex flex-col">
        {children}
```

- `min-h-screen` → `h-screen`: bounded viewport, faz `overflow-auto` do main realmente disparar.
- `min-h-0` em main: permite flex-1 encolher abaixo do conteudo intrinseco (essencial pra overflow-auto funcionar em flex-col).
- `min-h-full flex flex-col` no wrapper: short pages ainda preenchem; long pages rolam em main; filhos com `flex-1 h-full` funcionam cleanly.

**[WhatsAppChat.tsx:2327](../../../../src/components/chat/WhatsAppChat.tsx)** — remove math de viewport:
```diff
- <div className="flex flex-1 min-h-0 h-[calc(100vh-4rem)] max-h-[calc(100vh-4rem)] rounded-lg border bg-background overflow-hidden">
+ <div className="flex flex-1 min-h-0 rounded-lg border bg-background overflow-hidden">
```
Altura vem da cadeia flex: `h-screen → main flex-1 min-h-0 → wrapper flex-col flex-1 → page flex-1 → chat flex-1`.

**[WhatsAppChat.tsx:2367](../../../../src/components/chat/WhatsAppChat.tsx)** — fix horizontal clip:
```diff
- <div className={cn("flex-1 min-h-0 overflow-hidden flex flex-col", ...)}>
+ <div className={cn("flex-1 min-w-0 min-h-0 overflow-hidden flex flex-col", ...)}>
```
