# 2026-04-20

## Outbound idempotência — fechamento do ciclo (Tasks #1/#2/#3)

**Contexto**: Tasks #1 e #2 (sessão anterior) garantiram que `outbound-sender.ts` e `workflow-action-handler.ts` persistem `whatsapp_messages.message_id = key.id` retornado pela Evolution API, com `onConflict: "message_id,instance_id"`. Task #3 fecha o ciclo: o `evolution-webhook` precisava parar de usar `.insert()` bruto em 3 pontos que ainda criavam risco de duplicata / erro silenciado por string-match.

### Invariante consolidada

Toda escrita em `whatsapp_messages` (em qualquer edge function) usa `upsert` com `onConflict: "message_id,instance_id"`. O UNIQUE `(message_id, instance_id)` existe desde [20260127000000_add_whatsapp_messages.sql:37](../../../../supabase/migrations/20260127000000_add_whatsapp_messages.sql).

### Mudanças (Task #3 — Backend + Security + QA)

**[evolution-webhook/index.ts](../../../../supabase/functions/evolution-webhook/index.ts)** — 3 pontos convertidos de `insert` para `upsert`:

| Linha | Path | Política |
|---|---|---|
| `:978` | `messages.upsert` (inbound + outbound echo Evolution) | `ignoreDuplicates: true` — preserva content humanizado + `sent_by_ai` gravados pelo outbound-sender |
| `:1251` | Agent TTS reply (ptt) | `ignoreDuplicates: true` — copilot é fonte de verdade |
| `:1300` | Agent text reply | `ignoreDuplicates: true` — copilot é fonte de verdade |

Excluído da conversão: `:1461` (`send.message` handler) mantém `ignoreDuplicates: false` intencionalmente para atualizar `media_url` quando `MESSAGES_UPSERT` chega antes do URL de Storage correto.

Removido o swallow `if (!msgError.message?.includes("duplicate"))` — dead code após upsert; string-match em mensagem de erro é frágil e mascararia falhas reais.

### Decisão (CTO, 2026-04-20)

Caminho **conservador** (`ignoreDuplicates: true`): echo do Evolution não sobrescreve linha já persistida pelo outbound-sender. Justificativa: outbound-sender grava `content` humanizado + `sent_by_ai: true` que o echo não tem como melhorar. Delta de `status: sent → delivered/read` é coberto por outro handler (`messages.update`).

### Invariante global consolidada

**Toda** escrita em `whatsapp_messages` em `supabase/functions/**` usa `upsert` com `onConflict: "message_id,instance_id"`. Zero `.insert()` brutos permanecem.

**Política de `ignoreDuplicates` por contexto**:
- **Webhook echo handlers** (`evolution-webhook`, `sz-chat-webhook`): `true` — o webhook não é fonte de verdade, primeiro write vence.
  - **Exceção única**: `evolution-webhook` send.message handler usa `false` para permitir refresh do `media_url` quando `MESSAGES_UPSERT` chegou antes com URL null/CDN expirada. Anchorada por marker `SEND_MESSAGE_MEDIA_REFRESH` no código — contract test valida explicitamente via lookup no contexto acima.
- **Dispatchers/senders** (`outbound-sender`, `workflow-action-handler`, `followup-sender`, `ai-action-executor`, `campaign-rule-dispatch`, `pipe-rule-dispatch`, `process-scheduled-user-messages`): `false` — dispatcher é fonte de verdade para `content` humanizado + `sent_by_ai`.

### Contract test global

**[tests/unit/whatsapp-messages-idempotency-contract.test.ts](../../../../tests/unit/whatsapp-messages-idempotency-contract.test.ts)** — 5 asserts AST-grep em **todo** `supabase/functions/**`:
