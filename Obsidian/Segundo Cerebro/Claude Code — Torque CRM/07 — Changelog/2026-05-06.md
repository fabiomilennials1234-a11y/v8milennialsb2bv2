# 2026-05-06

## Mudancas
- **Upsell / Leads**: Corrigido delete de leads com entries em `upsell_clients` (FK RESTRICT bloqueava). Extraida funcao `cleanupLeadDependencies` unificando single e bulk delete.
- **Upsell / Import**: Import de clientes agora mostra erros detalhados por linha (collapsible UI no step "complete").
- **Upsell / Import**: Fallback de stage key quando `selectedStageKey` esta vazio usa primeiro stage da lista.
- **Leads / Delete**: Adicionado cleanup de `custom_pipe_entries` ao fluxo de delete (faltava).
- **Cache**: Invalidacao de `upsell_clients`, `custom_pipe_entries` em todos os hooks de delete.

## Arquivos tocados
- `src/hooks/useLeads.ts` — Extraida `cleanupLeadDependencies()`, unificada logica de delete single + bulk, adicionadas tabelas upsell + `custom_pipe_entries`, invalidacao de caches extras
- `src/components/upsell/ImportUpsellClientsContent.tsx` — Error tracking por linha (`ImportError[]`), UI collapsible de erros no step complete, fallback stage key, logging contextual

## Decisoes
- `ON DELETE RESTRICT` em `upsell_clients.lead_id` mantido intencionalmente. Cleanup explicito no frontend.
- `cleanupLeadDependencies` e uma funcao pura (sem verificacao de permissao) — a verificacao e responsabilidade do caller (`useDeleteLead`, `useDeleteAllLeads`, etc).

## Follow-ups
- Considerar mover `cleanupLeadDependencies` para edge function (server-side) para garantir atomicidade via transacao SQL
- Verificar se ha mais tabelas com FK para leads que possam causar RESTRICT em orgs com features novas
