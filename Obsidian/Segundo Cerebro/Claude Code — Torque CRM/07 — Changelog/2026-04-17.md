# 2026-04-17

## Fix Torque Analytics — dados reais em toda a aba Analytics

**Task**: Toda a área de Analytics/Dashboard exibia dados incorretos, zerados ou inconsistentes. Tratado como incidente de dados e produto. Objetivo: métricas rastreáveis a dados reais do banco, com fórmulas claras, validadas contra SQL manual.

### Diagnóstico (Conductor + DBA + Frontend)

Mapeamento completo da stack: 8 RPCs SQL, 10+ hooks React Query, 5 section components. 5 causas-raiz simultâneas:

1. **Date filter divergence (CRITICAL)** — `get_dashboard_metrics` usa `COALESCE(metrics_period_at, created_at)`, mas as 5 RPCs de analytics (`overview`, `commercial`, `financial`, `pipeline`, `engagement`) usavam bare `created_at` / `closed_at`. Dashboard e Analytics mostravam números diferentes para o mesmo período.
2. **Silent error fallback (CRITICAL)** — Todo hook fazia `if (error) { return EMPTY }` — UI mostrava zeros "bonitos" quando a RPC falhava, escondendo o erro real.
3. **Client-side aggregation divergence (HIGH)** — `useMktByOrigin` buscava TODOS os leads, confirmações, propostas e agregava no browser com lógica diferente das RPCs. Funil compacto do `TabAnalyticsV2` divergia do funil do `PipelineSection`.
4. **JS truthiness bug (HIGH)** — `(p.responsible_id || p.closer_id) === member.id` no `useConversionRates` retorna o primeiro truthy, não faz OR lógico. Conversion rate por membro estava errada.
5. **Missing `taxaConversao` (MEDIUM)** — Hook esperava campo que a RPC nunca retornou. Sempre 0%.

### Decisão de arquitetura

**Fonte de verdade temporal**: `COALESCE(metrics_period_at, created_at)` para leads, `COALESCE(metrics_period_at, closed_at)` para vendas. Aplicado uniformemente em TODAS as 7 RPCs de analytics.

**Error handling**: hooks DEVEM propagar erros (throw) para React Query expor `isError`. Componentes DEVEM mostrar banner de erro, nunca zeros silenciosos.

**Agregação**: lógica crítica consolidada no backend/RPC. Agregação client-side apenas para dados que dependem de config manual (investimento marketing).
